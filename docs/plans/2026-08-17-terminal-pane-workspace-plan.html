Implementation plan · 17 Aug 2026

From terminal tabs to a focused pane workspace.

Add right-click pane actions, horizontal and vertical splits, drag resizing, zoom/restore, and an unambiguous active-pane state—while keeping KubeCLI’s current terminals and resource panel stable.

Ready for implementation React 19 + TypeScript Tauri 2 + xterm.js No new runtime dependency
01 / DECISION

Use a pane tree, not a larger tab array.

Tabs and panes solve different jobs. A pane is a visible region; each pane owns a local tab group. A recursive tree expresses any split arrangement, and one focused leaf drives commands, resource-panel state, and keyboard shortcuts.

Recommended: split tree

Each split node stores direction and ratio; each leaf stores its tab IDs and active tab. Supports arbitrary nesting, resize, zoom, and close without position-specific state.

Rejected: fixed 2×2 grid

Simple initially, but cannot represent nested layouts cleanly. Empty grid cells and special-case resizing create poor DX and brittle state transitions.

Rejected: one tab per pane

Splitting would replace rather than complement tabs. Users would lose the lightweight tab workflow they already know, and tab-to-pane migration would be harder later.

Scope boundary: this plan includes local tabs, splitting, focus, zoom, resize, and closing. Dragging tabs between panes and persisting layouts across app launches are intentionally deferred.

03 / BEHAVIOR

One focus contract across every interaction.

A user should never wonder where the next command will run. Pane focus is updated before tab actions, context-menu actions, resource actions, or terminal input are dispatched.

Focus and highlight

  • Pointer-down in a pane, its header, or its local tab activates that pane.
  • The active pane gets a 2px inset teal outline and brighter header; its local active tab remains visually selected.
  • Only the active pane carries aria-current="true" and the visible FOCUSED label.
  • Resource actions snapshot the focused pane’s active tab ID before sending a command.

Split and close

  • Split Right replaces the focused leaf with a row split; Split Down uses a column split.
  • The existing leaf stays first. A fresh terminal tab is created in the second leaf at a 50/50 ratio and receives focus.
  • Closing a pane disposes all PTYs in that leaf, promotes its sibling, normalizes the tree, and focuses the nearest surviving leaf.
  • Close is disabled when only one pane remains.

Resize

  • Divider visual thickness is 1px; pointer hit target is 8px.
  • Use pointer capture so drag continues outside the divider.
  • Clamp ratios using a 240px minimum width and 120px minimum height per leaf.
  • Commit ratio on pointer-up; xterm’s existing ResizeObserver performs fit and backend resize.

Zoom and restore

  • Zoom stores only zoomedPaneId; it does not mutate the layout tree or ratios.
  • Siblings and splitters are hidden; the resource panel remains visible below the workspace.
  • The menu label becomes Restore Pane; repeating the action restores the exact previous layout.
  • Closing or removing the zoomed pane clears zoom before normalizing.
Existing right-click conflict: Terminal.tsx currently creates a Copy/Paste menu imperatively inside xterm. Replace it with one React menu: terminal-specific actions first, a separator, then pane actions. Right-clicking always focuses the target pane before the menu opens.

05 / STATE MODEL

A small discriminated union covers the workspace.

Tabs remain normalized records because terminal lifetime and panel state belong to a tab. Layout leaves reference those records.

type PaneId = string;
type TabId = string;

type LayoutNode =
  | { kind: 'leaf'; id: PaneId; tabIds: TabId[]; activeTabId: TabId }
  | {
      kind: 'split';
      id: string;
      direction: 'row' | 'column';
      ratio: number;          // first child share, clamped by rendered size
      first: LayoutNode;
      second: LayoutNode;
    };

interface WorkspaceState {
  root: LayoutNode;
  tabs: Record<TabId, Tab>;
  activePaneId: PaneId;
  zoomedPaneId: PaneId | null;
}

08 / ACCEPTANCE

Definition of done.

The feature is complete only when every interaction below is observable in a real application window and the automated gates pass.

  • Right-clicking any pane focuses it and opens a viewport-safe menu.
  • Menu contains Zoom/Restore, Split Right, Split Down, and Close Pane.
  • Terminal-body menu still provides Copy, Paste, and Clear Selection.
  • Split Right and Split Down create a fresh live PTY at 50/50.
  • Nested splits render correctly with no fixed-grid assumptions.
  • Both divider directions drag smoothly and honor minimum sizes.
  • xterm fits and backend rows/columns update after resize.
  • Exactly one pane has the teal active highlight at any time.
  • Click, tab click, terminal focus, and right-click all update active pane.
  • Resource actions execute in the focused pane’s snapshotted active tab.
  • Zoom hides siblings without destroying layout or ratios.
  • Restore returns to the exact pre-zoom arrangement.
  • Closing a pane disposes its PTYs and promotes its sibling cleanly.
  • The final pane cannot be closed, so the workspace is never empty.
  • Existing local tab add, close, cycle, resource-panel, and auth flows still pass.
  • Typecheck, full Vitest suite, frontend build, and Tauri smoke test pass.

Risk: too many live terminals

Splits make concurrent PTYs easier to create. Keep terminal lifetime tied strictly to tab records, dispose on close, and add no hidden duplicate instances during tree rerenders.

Risk: wrong command target

Ambient activeTabId can change between resource selection and pending-command delivery. Carry the target tab ID with the pending command and assert it in an integration test.
